# 部署指南

Font Subsetter 是纯静态页面：没有数据库、接口或服务端字体处理任务。你可以部署到 GitHub Pages，也可以用 Docker + Nginx 部署到自己的环境。

| 方式           | 适合场景                                         | 注意事项                                      |
| -------------- | ------------------------------------------------ | --------------------------------------------- |
| GitHub Pages   | 开源项目演示、文档站、无需自定义响应头的公开工具 | 可绑定自定义域名；不能配置 Nginx 的安全响应头 |
| Docker + Nginx | 正式环境、内网、需要安全头或自行控制域名与缓存   | 需要一台可运行 Docker 的主机                  |

## GitHub Pages

仓库已包含 [发布工作流](../.github/workflows/deploy-pages.yml)。创建 GitHub 仓库并推送到 `main` 后：

1. 打开 GitHub 仓库的 **Settings → Pages**。
2. 将发布源选择为 **GitHub Actions**。
3. 等待名为 `Deploy GitHub Pages` 的工作流完成。
4. 在工作流的部署结果或 Pages 设置页打开站点地址。

若仓库为 `OWNER/font-subsetter`，默认地址为：

```text
https://OWNER.github.io/font-subsetter/
```

工作流会自动使用 `/font-subsetter` 作为资源前缀，页面脚本和 CFF 子集引擎 WASM 都已适配该路径。

### 自定义域名或用户主页

如果站点部署在根路径，例如 `https://fonts.example.com/` 或 `https://OWNER.github.io/`，请在仓库的 **Settings → Secrets and variables → Actions → Variables** 新建变量：

```text
GITHUB_PAGES_BASE_PATH=/
```

自定义域名本身仍需要在 GitHub Pages 设置中绑定；该变量只负责让静态资源使用正确路径。

GitHub Pages 不提供 Docker/Nginx 中的 CSP、COOP、COEP 等自定义响应头。如果你的安全策略依赖这些响应头，请选择 Docker 部署。

## Docker + Nginx

在仓库根目录执行：

```bash
docker build -t font-subsetter .
docker run --rm --name font-subsetter -p 8080:8080 font-subsetter
```

然后访问 `http://localhost:8080`。容器只会提供静态文件，不会保存用户导入的字体或输入文本。

镜像内的 Nginx 已配置：

- `.wasm` 的 `application/wasm` MIME；
- 带 hash 的静态资源长期缓存；
- SPA fallback；
- COOP、COEP、CSP、`X-Content-Type-Options` 和基础 Permissions Policy。

### 临时关闭 CFF 裁剪

如果发现某类 CFF/PostScript 字体的产物异常，可在重建镜像时关闭 CFF 路径；TTF、WOFF 和 WOFF2 流程不受影响：

```bash
docker build \
  --build-arg PUBLIC_ENABLE_CFF_SUBSET=false \
  -t font-subsetter .
```

关闭后，CFF/PostScript 字体会在页面中提示暂未启用；不需要回滚整个应用。
